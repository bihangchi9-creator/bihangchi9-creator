# spike

**我在做让人与已有 Agent 一起工作的产品。**

从日常待办、简历共创，到飞书里的编码协作。<br />
给人好用的界面，给 Agent 清楚的现场与边界。

## 精选作品

### 01 / Folio
**你和你的 Agent，共用一张简历工作台。**<br />
`Web / PWA Beta` · `源码私有` · `协作项目`

你在工作台里创建、编辑简历；自己的外部 Agent 读取结构和版本，
提交整批修改提案，由你审阅取舍。**最终决定始终在你手里。**

不内置聊天机器人，也不在产品内调用模型：产品提供工作台，
智能来自你已经在用的 Agent。

[打开工作台 ↗](https://resume.puppytodo.ai/) · [公开 Agent Skill ↗](https://github.com/suntianchong/folio-resume-skill)

<sub>公开 Skill 由协作者的仓库维护；产品源码保持私有。</sub>

### 02 / 点点 · Diandian
**让人和 Agent 使用同一份任务事实。**<br />
`开发中` · `源码私有` · `协作项目`

人用轻量待办界面管理日常，Agent 通过友好层读取任务、执行工作、提交结果。
任务状态、历史和人工确认，让交接过程看得见，而不是散落在另一段聊天里。

基于 Vikunja 底座，自研界面与 Agent 协作层。
账号完善、生产部署与更广泛的设备验证仍在推进。

<sub>私有开发项目，暂不提供公开体验或源码链接。</sub>

### 03 / Lark Agent Bridge
**在飞书 / Lark 里，与本地编码 Agent 协作。**<br />
`开源` · `TypeScript` · `DSH / CLI / IDE 适配`

一个群，一段对话，一条钉住的运行时。把 DSH、CLI 智能体、
IDE 窗口或自定义适配器接进团队日常所在的地方；
连接中断时，不会偷偷换成另一条运行时。

[查看源码 ↗](https://github.com/bihangchi9-creator/lark-agent-bridge)

## 我关注的设计问题

- **共用现场，而不只是聊天。** 人与 Agent 应当基于同一份对象、版本和任务状态协作。
- **重要的决定，由人掌握。** 改动应当可审阅，有后果的动作需要明确决定。
- **先是好产品，再接 Agent。** 不接 Agent 也应当好用；接入时提供清楚的协作契约。
